This procedure takes you from a new account to a paid invoice. You need a Zcash wallet that can export an incoming viewing key (UIVK) or a Unified Full Viewing Key (UFVK).

## Create your account and connect your wallet

<Steps>

1. Open the [Lunaz dashboard](https://lunaz.example.com/dashboard) and go to the sign-in page.

2. Enter your email.

   Lunaz sends a one-time code to your email. A new email creates a new account.

3. Enter the code.

   You can set an account name later in Settings.

4. Get the incoming viewing key from your wallet.

   With zcash-devtool, run `wallet list-accounts`. The command prints the UIVK on the `UIVK:` line. On mainnet the UIVK starts with `uivk1`. If your wallet exports only a UFVK (`uview1`), use the UFVK. Lunaz keeps only its incoming part.

5. Make sure that the key is correct.

   :::caution
   MAKE SURE THAT THE KEY IS CORRECT BEFORE YOU SAVE IT. YOU CANNOT CHANGE IT AFTER YOU SET IT.
   :::

6. Paste the key in the dashboard onboarding and save it.

7. Open the API keys page and create an API key.

   :::caution
   COPY THE KEY AT ONCE. THE DASHBOARD SHOWS THE KEY ONE TIME ONLY.
   :::

8. Keep the key on your server.

</Steps>

## Create your first invoice

An invoice amount is in zatoshi. 1 ZEC is 100000000 zatoshi.

<Steps>

1. Send this request from your server. Replace the key with your API key.

   ```bash title="Create an invoice"
   curl -X POST https://api.example.com/v1/invoices \
     -H "Authorization: Bearer lz_your_api_key" \
     -H "Content-Type: application/json" \
     -d '{"amount_zat": 5000000, "expires_in_secs": 900}'
   ```

   The examples use the Lunaz API at https://api.example.com.

2. Read the response.

   ```json title="Response"
   {
     "id": "8f14e45f-ceea-4672-9b2d-5c1d0a7e3b11",
     "address": "u1q8x4example7shieldedaddress",
     "amount_zat": 5000000,
     "zip321_uri": "zcash:u1q8x4example7shieldedaddress?amount=0.05&memo=bHVuYXo6OGYxNGU0NWY",
     "status": "pending",
     "expires_at": 1792000900
   }
   ```

3. Save the `id` with your order.

</Steps>

## Show the QR code

<Steps>

1. Encode the `zip321_uri` value as a QR code.

2. Show the QR code to the buyer.

3. Tell the buyer to scan it with a Zcash wallet.

</Steps>

The URI also contains the address, the amount and the Lunaz fee as a second payment. A wallet fills these fields when the buyer scans the code. Always show the `zip321_uri` as it is. If you build your own request, the fee is lost.

## Receive the webhook

<Steps>

1. Open the webhooks page in the dashboard.

2. Enter the URL of your endpoint.

3. Copy the signing secret.

4. Send a test delivery from the dashboard.

5. Make sure that your endpoint returns a 2xx status.

6. Verify the `X-Lunaz-Signature` header of each request, and ignore event ids that you already processed. See [Webhooks](../../guides/webhooks/#verify-the-signature).

7. Wait for the `invoice.paid` webhook.

</Steps>

When the buyer pays, the status changes to `detected` and then to `paid` after one confirmation. Lunaz sends `invoice.paid` with this body.

```json title="invoice.paid"
{
  "id": "5dafb709-a848-464e-95c3-49154a5c7dfb",
  "created_at": 1791914886,
  "type": "invoice.paid",
  "invoice_id": "8f14e45f-ceea-4672-9b2d-5c1d0a7e3b11",
  "status": "paid",
  "amount_zat": 5000000,
  "received_zat": 5000000,
  "overpaid_zat": 0,
  "pending_zat": 0,
  "txid": "3b1c0f9e2a7d4c58b6e1a0f3d9c27b845e6a1f0d2c3b4a59687766554433221f",
  "swap": null
}
```

<Aside>
You can also follow the status live. See [Accept ZEC](../../guides/accept-zec/) for the WebSocket and polling options.
</Aside>
