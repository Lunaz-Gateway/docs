Lunaz sends a signed POST request to your endpoint when an invoice, swap, withdrawal or plan changes. Each account has one webhook URL and one signing secret.

## Set up the endpoint

<Steps>

1. Open the webhooks page in the dashboard.

2. Enter the URL of your endpoint.

3. Copy the signing secret.

4. Send a test delivery.

5. Make sure that your endpoint returns a 2xx status.

</Steps>

To change the secret, rotate it on the same page. The old secret stops working at once. See [Webhooks API](../../api/webhooks/) for the request format.

## Event types

| Type | When |
| --- | --- |
| `invoice.paid` | The invoice is `paid`. |
| `invoice.underpaid` | The invoice expired with a payment that is too small. |
| `swap.refunded` | 1Click refunded a swap. The invoice stays `pending`. |
| `swap.failed` | A swap failed. The invoice stays `pending`. |
| `swap.incomplete_deposit` | The buyer deposited less than the quoted amount. The invoice stays `pending`. |
| `withdrawal.updated` | The status of a withdrawal changed. |
| `plan.updated` | The plan of your account changed. |
| `test` | You sent a test delivery. |

## Verify the signature

Each request has these headers.

| Header | Value |
| --- | --- |
| `X-Lunaz-Event-Id` | The event id. It is the same on every attempt and equals `id` in the body. |
| `X-Lunaz-Signature` | `t=<unix seconds>,v1=<hex signature>` |

`t` is the time when Lunaz sent this attempt. `v1` is the hex HMAC-SHA256 of the string `{t}.{raw body}`: the value of `t`, a period, and the raw request body. The key is your webhook secret. Lunaz signs each attempt again with a new `t`. The body does not change between attempts.

:::caution
VERIFY THE SIGNATURE ON THE RAW BODY BEFORE YOU PARSE THE JSON. IF YOU PARSE FIRST, THE BYTES CAN CHANGE AND THE CHECK FAILS.
:::

To verify a request:

1. Get `t` and `v1` from `X-Lunaz-Signature`.
2. Compute the HMAC-SHA256 of `{t}.{raw body}` with your secret.
3. Compare the result with `v1` in constant time. Reject the request if they differ.
4. Reject the request if `t` is more than 300 seconds (5 minutes) from your current time. This stops replayed requests.
5. Keep the event ids that you processed. If you get an id again, return a 2xx status and do nothing.

<Tabs>
<TabItem label="Node.js">

```js title="verify.js"
import crypto from "node:crypto";

const TOLERANCE = 300; // seconds

export function verify(rawBody, header, secret) {
  const parts = Object.fromEntries(
    (header ?? "").split(",").map((p) => p.trim().split("=", 2)),
  );
  const t = Number(parts.t);
  if (!Number.isInteger(t) || !/^[0-9a-f]{64}$/.test(parts.v1 ?? "")) {
    return false;
  }
  if (Math.abs(Date.now() / 1000 - t) > TOLERANCE) return false;
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${t}.${rawBody}`)
    .digest();
  return crypto.timingSafeEqual(Buffer.from(parts.v1, "hex"), expected);
}
```

<TabItem label="Python">

```python title="verify.py"
import hashlib
import hmac
import time

TOLERANCE = 300  # seconds


def verify(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(p.strip().split("=", 1) for p in (header or "").split(",") if "=" in p)
    t, v1 = parts.get("t", ""), parts.get("v1", "")
    if not t.isdigit() or abs(time.time() - int(t)) > TOLERANCE:
        return False
    expected = hmac.new(secret.encode(), t.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, v1)
```

<TabItem label="Go">

```go title="verify.go"
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/hex"
	"strconv"
	"strings"
	"time"
)

const tolerance = 300 // seconds

func verify(rawBody []byte, header, secret string) bool {
	var t, v1 string
	for _, p := range strings.Split(header, ",") {
		k, v, _ := strings.Cut(strings.TrimSpace(p), "=")
		switch k {
		case "t":
			t = v
		case "v1":
			v1 = v
		}
	}
	ts, err := strconv.ParseInt(t, 10, 64)
	if err != nil {
		return false
	}
	if d := time.Now().Unix() - ts; d > tolerance || d < -tolerance {
		return false
	}
	got, err := hex.DecodeString(v1)
	if err != nil {
		return false
	}
	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(t + "."))
	mac.Write(rawBody)
	return hmac.Equal(got, mac.Sum(nil))
}
```

## Respond and retry

Return a 2xx status within 5 seconds. Lunaz treats any other status, and any network error, as a failure.

Lunaz tries each event up to 3 times: at once, after 10 s and after 60 s. If all 3 attempts fail, the event status changes to `failed`. Pending retries continue after a restart of Lunaz.

To send a failed event again:

1. Fix your endpoint.
2. Open the webhooks page in the dashboard.
3. Select the Failed tab.
4. Click Retry on the event, or click Retry all failed.

The event gets 3 new attempts. You can also read the invoice with the API to find a missed status change.

Your endpoint can receive the same event more than once. Each attempt has the same event `id` and the same body. Use the `id` to ignore a repeat.

## Events in the dashboard

The webhooks page shows every event with its status: `pending`, `delivered` or `failed`. Each event shows the number of attempts, the last HTTP status code or error, and the time of each attempt.
